#+TITLE: dsmr-mcp — Testing
#+OPTIONS: toc:2 num:nil

This page is the contributor reference for running the dsmr-mcp test suite:
the canonical entrypoints, the fast-versus-gated split, the pinned SBCL build
that keeps runs reproducible, and the project-local cache guard that prevents a
fatal fasl-cache crash on a developer machine.

See also: [[file:index.org]] · [[file:architecture.org]] · [[file:operations.org]] ·
[[file:installation.org]].

* Canonical entrypoints

Run the suite through the Makefile — a contributor and CI invoke the *same*
targets, so "it passes on my machine" and "it passes in CI" mean the same thing.

#+begin_src sh
make test              # fast in-process unit suite (run this constantly)
make test-integration  # slow cross-process suite (run before a release / on CI gate)
#+end_src

Both exit non-zero when any test fails: the =:perform (test-op …)= in
=dsmr-mcp.asd= signals an error on a failed leaf, and under =--disable-debugger
--non-interactive= an unhandled error terminates the process with a non-zero
code. No extra exit-code plumbing is needed.

ASDF has to find the checkout and its dependencies. Locally that resolution
goes through =$LISP_WORKSPACE= (and your =~/.sbclrc= / Quicklisp); in CI it
goes through =CL_SOURCE_REGISTRY= set to the checkout, or through Qlot /
Quicklisp. Every dependency resolves from the Quicklisp distribution *except*
=slynk-client=, which is sourced from a fork branch and is not published to
the dist — CI clones it, pinned to an exact commit, into a directory the
recursive =CL_SOURCE_REGISTRY= scans (see the workflow's vendor step), and a
local setup needs an equivalent checkout on the ASDF search path.

* Fast versus gated

The suite is split across two ASDF systems so the inner-loop run stays quick:

- =dsmr-mcp/tests= (=make test=) — true *in-process* unit tests. No test in
  this system forks a child process; the assertions are effectively free. This
  is the push hot-path: it runs on every push and every pull request.
- =dsmr-mcp/tests/integration= (=make test-integration=) — the *cross-process*
  tests. Each leaf here spawns a real child SBCL (a stdio server, a foreign
  Slynk image, or a hermetic worker pool) and so costs seconds-to-minutes per
  scenario. These run gated — on a schedule and on demand — not on every push.
  Each leaf skips cleanly (it reports a skip, not a failure) when the
  environment cannot spawn a child, so a constrained runner is never red-flagged.

The cost of a full run lives almost entirely in that integration system's
process spawning; keeping it off the push hot-path is what makes the fast suite
fast.

** A state home of its own for each run

=make test=, =make test-integration=, and =make test-warm= run under a fresh
=XDG_STATE_HOME= made for the run and removed when it ends, however it ends.
Several leaves start a session pool, and a pool publishes a record of its
workers where the host bus service looks for workers to stop or hibernate. A
test run must never be something a live service on your machine acts on. The
fasl cache is shared between runs as before.

** No =DSMR_= settings from the calling shell

The same three targets unset every environment variable whose name starts with
=DSMR_= before the test image starts, except names that start with
=DSMR_TEST_=. An assignment on the make command line is unset too. The test
image and every process it starts run with each setting's default, whatever the
calling shell or a project's =.envrc= exports.

A server started under the shell's bus identity joins that bus and can leave a
broker running after the run. A server started under the shell's attach target
can evaluate in the image you are working in. A test that needs a setting sets
it for itself and restores it afterwards.

=DSMR_TEST_= variables configure the suite rather than the server and pass
through unchanged. =DSMR_TEST_WORKER_CORE= is one; see
[[*Hermetic workers from the worker core]]. =DSMR_TEST_WATCHDOG_SECONDS= is
another; see [[*A time limit on each test]]. A setting that locates an optional
resource does not reach the run either: the HyperSpec leaf looks in
=$LISP_WORKSPACE/HyperSpec/= and skips when nothing is there, whatever
=DSMR_HYPERSPEC_DIR= says.

** A time limit on each run

=make test= and =make test-warm= stop after =TEST_TIMEOUT= (default 30 minutes).
=make test-integration= stops after =TEST_INTEGRATION_TIMEOUT= (default 90
minutes). A run past its limit receives SIGTERM, and SIGKILL =TEST_KILL_GRACE=
(default 90 s) later if it is still running. The grace exceeds SBCL's default
exit timeout of 60 s, so an orderly exit can still stop the session pool.

When a limit fires, stderr carries one line that names the target and the limit
as =VAR=value=. The recipe exits 124 when SIGTERM sufficed and 137 when SIGKILL
was needed, and make reports =Error 124= or =Error 137=. Every other exit status
passes through unchanged with no limit line. The run's private state home is
removed in every case.

The last test the log names is the one that was running when the limit fired.
Set a limit on the command line or in the environment, in =timeout(1)= duration
syntax; 0 turns a limit off:

#+begin_src sh
make test-integration TEST_INTEGRATION_TIMEOUT=2h
#+end_src

An interrupt (=C-c=) stops the run at once and is not subject to the grace.

** A time limit on each test

=make test-integration= runs each test under a per-test bound,
=DSMR_TEST_WATCHDOG_SECONDS=. The default is 600 s, several times the run time
of the slowest test in the suite. The first line of the test output states the
bound in force.

A test still running at its bound is stopped and fails. Above its result line,
the log shows a block with:

- the stopped thread's backtrace;
- the threads the test started, each with its backtrace;
- the descendant processes of the test process;
- the =/proc/locks= lines of the test process and those processes.

The Failures section names the test and the bound, and the run continues with
the next test. The run's final error lists every stopped test.

The stopped test's own cleanup runs. A cleanup still running 60 s later is
abandoned, and the block says so. The block ends with the processes and threads
still running after the stop. They are listed and never signalled: stopping them
is the test's own cleanup's job.

To set a different bound, pass the variable to the run:

#+begin_src sh
DSMR_TEST_WATCHDOG_SECONDS=900 make test-integration
#+end_src

0 turns the bound off. A value that is not digits with an optional decimal point
stops the run before the first test, with an error that names the variable.

=TEST_INTEGRATION_TIMEOUT= still limits the whole run, and ends a test the
per-test bound cannot stop, for example one blocked where interrupts are
deferred. =make test= and =make test-warm= run without a per-test bound.

** Bus binaries rebuilt before the run

=make test-integration= first runs =make bus-binaries=. It rebuilds
=bin/dsmr-bus-watch= with =make bus-watch= and =bin/dsmr-bus-host= with
=make bus-host= when the binary is absent or older than any file it is built
from, and leaves a current binary alone. The integration cases run these two
files from the checkout's =bin/=; nothing is installed anywhere else.

A binary is built from its system definition file and every file of every
system in its ASDF dependency closure, resolved with the same ASDF setup as its
build. For the host service that includes the Lisp workspace checkouts and the
Quicklisp libraries it links. An edit to =dsmr-mcp.asd= or to
=src/bus/watch.lisp= rebuilds both binaries. Two changes fall outside that set:
a change to a build recipe alone, and a system that an =.asd= file loads by
itself rather than declaring. After either, run =make bus-watch= or
=make bus-host= yourself.

A stale binary is removed before it is rebuilt, and a failed listing or rebuild
stops make before the suite starts, so no case runs against old code. Listing
takes about ten seconds on a warm fasl cache, and a rebuild adds one build. The
step runs before =TEST_INTEGRATION_TIMEOUT= starts counting, and without the
calling shell's =DSMR_= settings, like the suite.

#+begin_src sh
make bus-binaries                              # bring both binaries up to date alone
make -n test-integration                       # show a pending rebuild; changes nothing
make bus-sources BUS_SOURCES_DIR=/tmp/lists    # list the files each binary is built from
#+end_src

** Hermetic workers from the worker core

Integration leaves that need workers booted from the worker core get one from
the fixture =worker-core-for-tests= in =tests/integration/support.lisp=. It
builds a worker core from this tree into a scratch directory once per test
process, removes it when the process exits, and never touches the
=dsmr.core.worker= in the checkout. A leaf that cannot get a core skips and says
why, through =with-worker-core-or-skip=. The build takes about ten seconds on a
warm fasl cache; to skip it while iterating, build one yourself and point
=DSMR_TEST_WORKER_CORE= at it:

#+begin_src sh
make core-worker WORKER_CORE=/tmp/my-worker.core
DSMR_TEST_WORKER_CORE=/tmp/my-worker.core make test-integration
#+end_src

The leaves that save and resume worlds (=worker-hibernate-test=,
=pool-hibernate-test=, =pool-resume-test=, =pool-requests-test= and the end to
end =pressure-relief-test=) spawn real workers and live in
=make test-integration= only; =make test= never hibernates anything.

* Pinned SBCL build, and why it matters

CI pins the SBCL build to the upstream prebuilt binary (=sbcl-bin/2.5.5=). That
binary has one fixed garbage-collector flavor — the pinned =sbcl-bin= ships the
=MARK-REGION= collector — so every CI run compiles and loads fasls under the same
flavor and the cache is always coherent.

This matters because SBCL keys its compiled-fasl cache on the implementation
*version string* but not on the GC flavor. Two SBCLs that share a version string
but were built with different collectors (for example a stock =GENCGC= build
versus a =MARK-REGION= build) write fasls into the same cache directory yet
cannot load each other's output: loading a fasl from the wrong flavor aborts
with =INVALID-FASL-FEATURES=. Pinning a single build removes the ambiguity — and
a prebuilt =--core= image is immune by construction, because SBCL refuses to load
a core produced by a different build at all.

You can fingerprint a running SBCL with =(lisp-implementation-version)= together
with the GC-related markers in =*features*= (e.g. =:mark-region-gc= vs
=:gencgc=); a cache built under one fingerprint should only be loaded by an SBCL
with the same one.

* The local cache guard

=make test= isolates its fasl cache to a project-local directory
(=XDG_CACHE_HOME= defaults to =.ci-cache/= under the project root) instead of
the shared =~/.cache/common-lisp=. This is deliberate: on a developer box whose
=sbcl= was rebuilt with a different GC flavor than the one that populated the
shared cache, a plain run would try to load flavor-mismatched fasls and crash
with =INVALID-FASL-FEATURES=. Pointing the cache at a project-local directory
turns that crash into a clean cache miss followed by a recompile — the suite
just rebuilds what it needs and runs.

If you ever hit =INVALID-FASL-FEATURES= from a tool that does *not* go through
the Makefile, the fix is the same: clear the offending cache directory and let
it recompile, or point =XDG_CACHE_HOME= at a fresh directory for that run.

=.ci-cache/= (and the profiling harness's =.measure-cache/=, and any prebuilt
=dsmr.core=) are build artifacts — they are git-ignored and never committed.

* Measured numbers

These tables are an illustrative snapshot, not an invariant: the wall-clock
figures and pass counts drift as leaves are added and the toolchain moves, so
read them as "what one run looked like on the build below," not as a contract.

Recorded on the development box (=sbcl 2.6.5=, isolated =.ci-cache=) and on a
GitHub =ubuntu-latest= CI runner (pinned upstream =sbcl-bin=, ASDF 3.3.7).

Development box:

| Run | Command | Wall clock | Result |
|-----+---------+------------+--------|
| Cold fast suite (empty cache) | =make test= | ~2 min 33 s | 1364 pass / 0 fail |
| Warm fast suite (core image) | =make test-warm= | ~1 min 25 s | 1364 pass / 0 fail |
| Core image build | =make core= | ~14 s (warm) | 175 MB =dsmr.core= |
| Worker core build | =make core-worker= | ~12 s (warm fasl cache) | 149 MB =dsmr.core.worker= |

CI runner (observed on the first pull-request run):

| Stage | Wall clock | Result |
|-------+------------+--------|
| Dependency prime (download dist + compile, cold cache) | ~27 s | — |
| Fast suite (=make test=) | ~1 min 47 s | 1364 pass / 0 fail |
| Integration job on a push/PR | — | skipped (gated) |

The CI fast job completes well within a few-minute budget. Its warm fast-suite
time tracks the dev box's (~1.5–2 min), confirming the same conclusion: the
floor is set by the in-process timed-wait tests, not by load or compilation.

The cold fast suite is comfortably under a 3-minute budget. The warm number is
dominated not by load or compilation — the core image removes both — but by a
handful of in-process tests that deliberately wait on a slynk debugger break or
a condition-variable timeout (the =attach/inspect-*= and elicitation leaves).
Driving the warm fast suite below ~45 s therefore depends on trimming those
timed waits, not on further caching; that work is tracked separately.

The gated integration suite (=make test-integration=) runs in minutes — each
leaf spawns a real child SBCL — and is intentionally kept off the push hot-path.
